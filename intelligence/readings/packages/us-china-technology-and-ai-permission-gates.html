# U.S.–China Technology and AI Permissions Constitution — 2026

**Wave:** China deepening wave 6
**Evidence cutoff:** 2026-09-24
**Question:** Who may sell, buy, operate, train, host, support, invest in or transfer which advanced technologies across the U.S.–China boundary?

## Bottom line

There is no single U.S.–China technology restriction. There is a stack of object-specific permission systems:

`jurisdiction -> classification/threshold -> destination -> entity/ownership -> end user/end use -> knowledge -> license/exception/review -> transaction -> delivery/access -> authorized use`

The controlling question changes with the object. A license for an advanced chip does not itself authorize a model-training service, remote access by another end user, transfer of controlled model weights, release of controlled technology to an employee, export of a Chinese dataset, operation of a public generative-AI service in China or a capital investment. Each must be tested separately.

Seven findings orient the current system:

1. **The United States controls more than physical exports.** The Export Administration Regulations (EAR) can reach reexports, in-country transfers, certain foreign-made direct products, releases of controlled technology or source code to foreign persons, specified end uses and specified U.S.-person support.
2. **China is not under a blanket chip embargo.** Product thresholds, end users, end uses and license policies differ. Since January 13, 2026, BIS reviews specified H200-, MI325X- and similar-chip applications case by case when named security, testing, capacity and customer conditions are met. Eligibility for review is not a license, shipment, installation or use receipt.
3. **AI compute, training, weights and inference are distinct.** Current EAR provisions separately address advanced-computing commodities, remote end users, advanced-model training and storage/transfer of specified model weights. In a specific VEU condition, API access and infrastructure used only for inference are distinguished from prohibited training; that clause must not be generalized into an unrestricted global API rule.
4. **Investment screening is a second gate.** CFIUS reviews covered foreign investment into U.S. businesses; the outbound program prohibits or requires notice for specified U.S.-person investments involving covered Chinese semiconductor, quantum and AI activities. Neither is a substitute for export authorization.
5. **China also operates export, entity, procurement, data and service gates.** Its dual-use rules require item/end-user/end-use review and licensing; its Unreliable Entity List can restrict China-related trade or investment; cross-border data rules turn on data type, operator and volume; public generative-AI services can require security assessment and algorithm filing.
6. **Nationality is not a complete talent rule.** A U.S. deemed-export question turns on whether controlled technology or source code is released, the recipient's status and nationality/permanent residence, classification and destination rule. Publicly available information and qualifying fundamental research are treated differently. China-side research, employment, data and technology-export rules create separate gates.
7. **Permission is not operation.** A rule, exception, application, license, investment notice or model filing proves only its own stage. Delivery, installation, compute allocation, training run, deployed model, user access and commercial output require later receipts.

## 1. The permission constitution

For every technology claim, identify all nine fields:

| Field | Required question |
|---|---|
| Object | Is this a chip, server, equipment, material, software, source code, technology, model weight, compute service, dataset, public service, capital interest or human service? |
| Jurisdiction | Why is the object or activity subject to U.S. or Chinese law? |
| Threshold/classification | Which ECCN, control-list entry, performance threshold, data class, service category or covered-activity definition applies? |
| Actor | Exporter, reexporter, transferor, cloud provider, model developer, investor, recipient, employee, ultimate parent, end user or public-service provider? |
| Destination and ownership | Where does the item/access go, and where are the entity and ultimate parent headquartered or controlled? |
| End user/end use | Civil, military, military-intelligence, advanced-node fabrication, supercomputing, surveillance, public information service or another named use? |
| Knowledge | What did the regulated person know, have reason to know or deliberately avoid learning? |
| Decision | No license required, exception, license, case-by-case review, presumption of denial, prohibited transaction, notification, filing, security assessment or national-security review? |
| Operating receipt | Was the object shipped, delivered, installed, accessed, trained, transferred, deployed or used as authorized? |

If one field is missing, “China can/cannot access the technology” is usually too broad.

## 3. U.S. control stack

### A. EAR jurisdiction comes before the China question

The first inquiry is whether an item, software or technology is **subject to the EAR**. Only then do classification, destination, end-user, end-use, foreign-direct-product, de minimis, U.S.-person and license-exception questions follow. EAR99 does not mean “uncontrolled everywhere”; end-use, end-user and embargo rules can still require authorization.

The rule is transaction-specific. An Entity List entry supplies the license requirement and review policy printed for that entry; it is not automatically a universal ban on every exchange with every affiliate. Current ownership and address rules must also be tested.

### B. Advanced compute is tiered, not binary

BIS's January 13, 2026 rule moved Nvidia H200-, AMD MI325X- and similar products to case-by-case review for China when applicants demonstrate:

- no reduction in global semiconductor production capacity available to U.S. customers;
- Chinese purchaser export-compliance procedures, including customer screening; and
- independent U.S. third-party performance and security testing.

This is **license-review eligibility under conditions**, not a general authorization. The operating clock is:

`classification -> application -> license decision -> conditions -> shipment -> customs delivery -> installation -> remote-access/customer controls -> actual workload`

The public press release proves only the review policy. It does not identify approved customers or delivered units.

### C. Hardware, training, weights and inference must remain separate

Current EAR materials show several different controls:

- advanced-computing commodities and servers;
- remote end users of licensed AI commodities, including parties in or headquartered/ultimately parented in China;
- training of models specified by ECCN 4E091 under certain VEU conditions;
- storage and transfer of specified model weights;
- a Know Your Customer red flag where IaaS supports training whose resulting controlled weights may be exported;
- API/inference treatment that can differ from training within a particular authorization.

Therefore:

- possession of licensed chips does not authorize every remote user;
- cloud access does not necessarily authorize export of trained weights;
- inference is not training;
- a model endpoint is not proof that the customer possesses the weights;
- open publication and closed transfer can have different treatment;
- a stayed provision must not be treated as an operative duty during the stay.

### D. Talent controls follow the released technology

EAR §734 treats release of controlled technology or source code to a foreign person in the United States as a deemed export, generally to the person's most recent country of citizenship or permanent residence. Releases can occur through revealing visual inspection or oral/written exchange. BIS separately recognizes exclusions and authorizations, including publicly available information and qualifying fundamental research.

The safe research statement is not “Chinese nationals cannot work on advanced technology.” It is:

> Access requires an object-level review of the technology/source code, its classification, the release, the person's status, applicable destination rule and any license or exclusion.

### E. Capital permissions are parallel, not derivative

The outbound investment program, effective January 2, 2025, covers specified U.S.-person transactions involving covered Chinese, Hong Kong and Macau persons engaged in defined semiconductor/microelectronics, quantum or AI activities. It separates prohibited, notifiable and excepted transactions and uses knowledge, indirect-investment and controlled-foreign-entity rules.

CFIUS works in the opposite direction. It can review foreign control transactions and certain non-controlling investments involving a TID U.S. business—one that deals in critical technology, specified critical infrastructure or sensitive personal data. Some critical-technology transactions require mandatory declarations based on whether a U.S. regulatory authorization would hypothetically be required for the relevant foreign acquirer or ownership-chain person.

Neither program licenses an export. A transaction can pass one gate and fail another.

## 4. China's control stack

### A. Dual-use export controls

China's 2024 Dual-Use Items Export Control Regulation, effective December 1, 2024, covers controlled goods, technologies, services and related technical data transferred from China or supplied by Chinese persons to foreign organizations or individuals. It provides:

- individual licenses, general licenses and registration-based export certificates;
- end-user and end-use documentation and verification;
- duties to stop and report when end user/use changes or documentation is defective;
- concern and control lists for importers/end users;
- customs holds while classification is resolved; and
- records retained for at least five years.

China consolidated its dual-use list into ten categories. Separate announcements can add item-, destination- or entity-specific restrictions. A list entry or announcement proves the legal gate; an issued license and customs release prove a permitted transaction.

### B. Restricted technology and countermeasure systems

China's Catalogue of Technologies Prohibited or Restricted from Export is a different object from the dual-use list. The July 15, 2025 adjustment and the 2026 licensing procedures demonstrate that restricted technology exports require authorization; the catalogue must be checked at the time of a proposed transfer.

The Unreliable Entity List can restrict or prohibit China-related import/export activity, new investment and other dealings. The 2025 implementing regulation for the Anti-Foreign Sanctions Law supplies another countermeasure route. These are actor- and measure-specific powers, not proof that all U.S. technology firms are barred.

Operating examples show real use of the system: in 2025 China listed named U.S. defense/technology firms and imposed specified trade and investment restrictions; later China suspended or adjusted some export-control-list measures as part of bilateral trade consultations. This demonstrates that countermeasures can be legally operative and diplomatically adjusted. It does not prove that every listed firm had material China revenue or that every announced restriction changed shipments.

### C. Cross-border data is a threshold system, not blanket localization

China's March 2024 cross-border-data rules separate:

- data without personal or important data used in activities such as international trade, transport, academic cooperation, multinational production and marketing;
- contract, human-resources, emergency and other exemptions;
- low-volume personal-data transfers by non-CIIO processors;
- standard-contract/certification routes; and
- security-assessment routes for CIIO personal/important data, non-CIIO important data and higher personal/sensitive-data volumes.

The decision must identify the data class, processor, CIIO status, annual transfer volume and destination/purpose. “China requires all data to stay in China” is false.

### D. Public AI service is not the same as private R&D

The 2023 Interim Measures apply to generative-AI services offered to the public in China. Research and development not offered as a public service is not automatically the same regulatory object. Public-opinion or social-mobilization services may require security assessment and algorithm filing; providers have duties involving lawful training data and foundation models, intellectual property, personal information, content safety and explanations to regulators.

China's public filing notices provide an operating receipt for **registration of named services/models**. They do not prove model accuracy, complete legal compliance, user scale or permission to export weights or data. The 2025 AI-generated-content labeling rules, effective September 1, 2025, add explicit and implicit labeling obligations. China announced a 2026 enforcement campaign that includes unfiled large models, weak safety review, training-corpus security and missing labels; an enforcement campaign is proof of regulatory attention, not proof that every provider violated the rules.

## 5. Claim audit

| Claim | Ruling | Reason |
|---|---|---|
| “The United States banned AI chips to China.” | **Overstated** | thresholds, entities, end uses and license policies differ; specified H200/MI325X-class applications became case-by-case in January 2026 |
| “H200 sales to China are approved.” | **Not established as a general fact** | a review policy is not an issued license, named customer, shipment or delivery receipt |
| “If China can rent U.S. cloud compute, it can legally train any model.” | **False** | cloud training, commodity remote access, model-weight export and end-user/end-use controls are separate |
| “API access gives the user the model weights.” | **False** | inference access and weight custody are technically and legally distinct |
| “U.S. export controls bar Chinese students from advanced research.” | **False as a blanket statement** | the rule follows controlled technology/source code, release, status, classification and authorization; public/fundamental research can differ |
| “CFIUS approves exports.” | **False** | CFIUS reviews covered inbound investment; BIS and other regulators control exports |
| “Outbound investment rules ban all U.S. investment in China.” | **False** | the program is technology-, activity-, entity-, transaction- and knowledge-specific and includes prohibited, notifiable and excepted transactions |
| “China localizes all data.” | **False** | the 2024 rules include data-type, volume and purpose-based exemptions and multiple transfer routes |
| “A Chinese generative-AI filing means the model is government approved.” | **Overstated** | it proves the filing/registration state required for the service, not a warranty of output, security or every legal obligation |
| “China's counter-controls are only rhetoric.” | **False** | named entity and export-control measures have been formally issued, adjusted and in some cases suspended; shipment effect remains a separate empirical question |
| “A standards dialogue harmonizes market access.” | **False** | dialogue or standards work does not itself issue a product, data, investment or service authorization |

## 6. What to measure next

1. **License outcomes:** product, ECCN, applicant, customer, end use, conditions and decision date where lawfully public—not aggregate rumor.
2. **Delivery:** customs/shipping, installation and workload evidence for any licensed advanced-computing product.
3. **Remote access:** intended and actual IaaS users, ultimate parents, access geography and inference-versus-training function.
4. **Model weights:** classification, custody, storage jurisdiction, transfer authorization and whether publication changes the analysis.
5. **U.S.-person support:** named service, tool/facility, knowledge, license and actual work performed.
6. **Deemed exports:** the controlled technology actually released, recipient status and access-control record; nationality alone is insufficient.
7. **Investment:** prohibited/notified/excepted analysis, closing, governance rights and covered activity financed; CFIUS and outbound clocks separately.
8. **Chinese export controls:** item/list code, destination, end user/use, license, customs release and delivery.
9. **Chinese countermeasures:** named entity, legal measure, effective/suspension dates, transaction exposure and observed trade/investment effect.
10. **Data transfers:** data class, CIIO status, annual volume, lawful route, assessment/contract/certification and actual transfer.
11. **Public AI:** model/service filing number, security assessment where required, labeling implementation, enforcement and active service.
12. **Standards/research:** adopted standard, public paper, dataset or repeat institutional mechanism—not an announced intention alone.

## Governing boundary

This constitution is an orientation, not transaction-specific legal advice. Controls change quickly and can turn on unpublished license conditions or facts not visible in public sources. Before using any conclusion operationally, recheck the current regulation, lists, entity ownership, applicable thresholds, effective dates, stays, exceptions and the exact parties and end use.

The evidence ladder is:

`rule -> classification -> application/filing -> decision -> conditions -> transaction -> delivery/access -> authorized use -> measured output`

No earlier stage proves a later one.
